## 更新详情

v0.2.2 是一次覆盖启动器主要流程的功能版本：首页加入可切换字形与动效的 ASCII 标题；`Versions` 支持 Fabric、Quilt、Forge、NeoForge 与 OptiFine；`Instances` 新增实例模组面板；Java 运行时可跨磁盘扫描并直接下载 Temurin JDK；`Downloads` 历史改为持久化；设置里可以检查并安装启动器更新；退出启动器时会一并停止游戏进程。

### 首页标题与动效

- 首页标题改为四行 ASCII 大字 `MCTL`，支持 `Block`（实心方块）和 `Line`（线条）两种字形。
- 新增 `Sheen`（扫光）、`Wave`（流动）、`Breathe`（呼吸）和 `Off`（静态）四种动效，可在设置中切换，也可在设置行直接按 `←` / `→` 循环切换。
- 标题颜色跟随当前主题与强调色；窄终端会自动回退为单行文字。
- 标题只有在首页且没有弹窗时才会运行动画，减少空闲刷新。

### 模组加载器

- `Versions` 按 `l` 打开加载器面板，可选择 Fabric、Quilt、Forge、NeoForge 或 OptiFine。
- Fabric / Quilt 使用官方 meta profile；Forge / NeoForge 使用 Maven 安装器；OptiFine 使用本地 `OptiFine_<version>_<edition>.jar` 运行 Patcher。
- 加载器会注册为独立本地版本，通过 `inheritsFrom` 继承原版，实例继续引用加载器版本，不复制共享库和资源。
- Forge / NeoForge 会先下载并校验安装器依赖，再以离线模式运行安装器，避免官方站点探测和慢镜像导致长时间卡住。
- NeoForge 支持 1.20.1 和 1.20.2+ 的版本格式，并统一登记为 `<mc>-neoforge-<version>`，避免与 Forge 版本目录冲突。
- 加载器版本列表、Fabric Maven、NeoForge Maven 都支持可选镜像，可指向 USTC / BMCLAPI 等加速节点。
- OptiFine 生成补丁客户端、launchwrapper 和 `--tweakClass` 参数，启动时使用补丁 jar。

### 实例模组管理

- `Instances` 按 `m` 打开所选实例的模组面板。
- 支持添加本地 `.jar`、启用/禁用、删除、重新扫描和打开模组目录。
- 读取 Fabric、Quilt、Forge、NeoForge 与旧版 Forge 的元数据，显示模组名称、版本和适用加载器。
- 禁用的模组会重命名为 `.jar.disabled`，再次启用时恢复 `.jar`。

### Java 运行时

- 扫描范围扩展到 PATH 的每一项、`JAVA_HOME`、`JDK_HOME`、`JRE_HOME`、Windows 注册表、所有 Windows 固定磁盘的常见 Java 目录，以及 IntelliJ / PyCharm / Android Studio 自带运行时。
- 修复了 `bin/java` 通配符匹配被当作目录而丢弃的问题；D 盘等非系统盘的 Java 现在可以被发现。
- Java 选择器底部可直接下载 Adoptium Temurin JDK 8、17 或 21。
- JDK 下载支持 HTTP Range 断点续传、SHA-256 校验和 GitHub 镜像加速；下载完成后解压到数据目录的 `java/temurin-<版本>/`，自动设为当前运行时并重新扫描。
- 设置中的 Java 运行时行仍支持手动输入 `java.exe` 或 JDK 目录。

### 下载历史

- `Downloads` 的最近 20 条任务记录改为持久化保存到数据目录的 `downloads-history.json`。
- 启动器启动时自动加载；切换数据目录时会加载新目录的历史。
- 文件损坏时会安全忽略，不影响启动器启动。
- 任务完成、失败或取消后立即原子写入，退出启动器后仍可查看。

### 应用内更新

- 在 `Settings` 的 `Launcher version` 行按 `enter` 检查 GitHub Releases。
- 支持下载当前平台对应的启动器压缩包，校验 SHA-256 后替换可执行文件，重启启动器完成升级。
- GitHub 无法直连时会自动尝试 `gh-proxy.com`、`ghfast.top`、`ghproxy.net` 等镜像，也可用 `MCLAUNCHER_UPDATE_MIRROR` 指定镜像前缀。
- 开发版（`dev`）不会执行更新检查。
- Windows 下采用“先移走旧可执行文件、再写入新文件”的方式替换正在运行的启动器；旧文件会在下次启动时清理。

### 退出与进程

- 退出启动器（`q` / `ctrl+c` / 正常退出）时会先停止由它启动的游戏进程，不再留下后台 Java 进程。
- 先尝试正常停止并等待最多 2 秒，超时后强制结束整个进程树；再等待最多 1 秒确保退出。
- 游戏启动绑定到启动任务上下文，覆盖“Java 已启动但游戏状态尚未写入界面”的短暂窗口。
- Bubble Tea 异常退出时也会执行一次游戏进程清理。

### 修复与改进

- 修复 Java 扫描只接受目录匹配、导致大量 `.../bin/java` 候选被丢弃的问题。
- 加载器版本列表的超时从 45 秒放宽到 90 秒，减少慢网络下误报失败。
- 修复 Forge 安装器的证书探测卡死、镜像路径拼接错误和依赖库下载不稳定问题。
- 修复 OptiFine 本地库被错误补全为远程下载地址的问题。
- 修复 NeoForge 1.20.1 与 Forge 版本目录重名的问题。
- 改善慢镜像下的下载体验：增加下载停滞检测、镜像回退和下载历史持久化。
- 更新了 README、预览页面和全部文档截图。

### 平台与兼容性

- Windows、Linux、macOS 的 `amd64` / `arm64` 构建目标保持不变。
- 旧版 `config.json`、账户、实例、数据目录和已安装版本继续兼容。
- 新增数据文件：`downloads-history.json`（下载历史）和 `java/`（启动器内下载的 JDK）。
- 加载器版本使用独立的 `<mc>-forge-<version>`、`<mc>-neoforge-<version>`、`fabric-loader-<version>-<mc>`、`quilt-loader-<version>-<mc>` 或 `<mc>-OptiFine-<edition>` 目录。
- JDK 下载使用 Adoptium API 解析版本，实际文件优先走 GitHub 镜像；具体可用版本取决于平台。
- 应用内更新适用于正式发布版；从源码构建的 `dev` 版本会提示无法检查更新。

### 升级说明

可以直接使用应用内更新，或下载新版本压缩包替换旧可执行文件；不需要迁移数据或修改配置。

1. 关闭正在运行的启动器和游戏。
2. 用新版本压缩包中的可执行文件替换旧文件，或在 `Settings → Launcher version` 中检查更新。
3. 启动后原有的账户、实例、主题、数据目录和已安装版本都会保留。

如果之前通过 `--data-dir` 或 `MCLAUNCHER_DATA_DIR` 指定了数据目录，升级后继续使用相同参数即可。下载历史会保留在对应数据目录的 `downloads-history.json` 中。

### 安装

从下方 Assets 下载对应平台的压缩包：

- Windows：`mclauncher_0.2.2_windows_amd64.zip` / `mclauncher_0.2.2_windows_arm64.zip`
- Linux：`mclauncher_0.2.2_linux_amd64.tar.gz` / `mclauncher_0.2.2_linux_arm64.tar.gz`
- macOS：`mclauncher_0.2.2_darwin_amd64.tar.gz` / `mclauncher_0.2.2_darwin_arm64.tar.gz`

校验和见 `checksums.txt`。macOS 首次运行如被系统拦截：

```bash
xattr -d com.apple.quarantine ./mclauncher
```
